# Plan tasks

1. Read the linked Issue and current product and technical documents.
2. Use the repository's chosen task-plan location and locale.
3. Assign stable task IDs such as `SP<issue>-T1`.
4. For every task record owner, dependencies, affected area, done-when, and
   exact repository-native verification commands.
5. Map each acceptance criterion or behavior identifier to at least one
   implementation or verification task.
6. Separate implementation, verification, documentation, and handoff tasks.
7. Identify unresolved decisions instead of inventing them.

Planning does not implement or approve the work.
