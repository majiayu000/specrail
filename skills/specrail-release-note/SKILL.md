# Release note

1. Confirm the PR is merged and identify the linked Issue and included commits.
2. Read the final diff and current user-facing requirements.
3. Summarize user-visible changes, verification, migration or rollback notes,
   limitations, and known risks.
4. Use the caller's language while preserving stable identifiers and commands.

Drafting does not publish a release. Publish only when the caller explicitly
requests and authorizes it.
