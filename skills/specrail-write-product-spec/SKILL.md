# Write product requirements

1. Confirm the linked Issue and search for existing requirements.
2. Use the repository's selected path, locale, and product template.
3. Define problem, affected users, goals, non-goals, user-visible behavior,
   boundaries, failure behavior, and measurable acceptance criteria.
4. Give stable identifiers to requirements that later tasks must reference.
5. Record unresolved product decisions explicitly.

Do not invent implementation details or begin coding unless the caller
separately requests implementation.
